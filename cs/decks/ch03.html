This chapter in a nutshell

Sorting puts data in ascending (smallest first) or descending order.

Bubble sort compares pairs and swaps; it uses brute force and is the slowest.

Merge sort splits the list, then merges (divide and conquer).

Linear search checks items one by one; binary search halves a sorted list.

Choose the algorithm to suit the data. In the exam you must show the intermediate stages.

Why sort and search

  1. Millions of items may be stored, so searching must be efficient.
  2. Sorted data is far easier to search, like a dictionary in alphabetical order.
  3. Sorting arranges items in ascending order (1, 2, 3) or descending order (3, 2, 1).
  4. Some algorithms are more efficient than others.

Bubble sort

Sorting and searching algorithms

Bubble sort

How it works (1/2)

Pass

One complete traversal (trip along) the list comparing pairs.

  1. Start at the beginning of the list.
  2. Compare the values in positions 1 and 2. If they are not in ascending order, swap them.
  3. Compare positions 2 and 3, and swap if necessary.
  4. Continue to the end of the list.
  5. If there have been any swaps, repeat from the beginning. Stop when a whole pass has no swaps.

Bubble sort

How it works (2/2)

Exam tipIt is called bubble sort because the largest items gradually move to the end like bubbles rising in water. After pass 1 the largest is in place, after pass 2 the next largest, so the last comparisons can be left out to make it more efficient.
CarefulA computer needs one extra pass with no swaps to know the list is sorted. It cannot just look at all the numbers at once.

Bubble sort

The flowchart variables

  1. position starts at 1 and moves along the list.
  2. length is the length of the list.
  3. switch (swap counter) is reset to 0 at the start of each pass and increased by 1 every time two items are swapped.
  4. At the end of a pass, if switch is 0 the list is sorted.

Merge sort

Sorting and searching algorithms

Merge sort

How it works (1/3)

Recursion

Repeatedly applying a method to the results of a previous application of the same method.

  1. Split the list into two halves, then split again, until every list has one item. A one-item list is already sorted.
  2. Merge the lists back together in order.
  3. When merging, compare the leftmost (lowest) item in each list and put the smaller into the new list first.
  4. Repeat until all items are merged into one sorted list.

Efficiency of sorting algorithms

Efficiency of sorting algorithms

Efficiency of sorting algorithms

Bubble sort

Uses brute force: starts at the beginning and repeats the same task over and over until it finds a solution. It is the slowest.

Merge sort

Uses divide and conquer: repeatedly breaks the problem into smaller sub-problems, solves them and combines the solutions. One of the most efficient.

  1. Bubble sort is far slower for lists of more than about 1000 items.
  2. For small lists the time difference is too small to matter.
  3. Bubble sort is easier to code, so it can be a good choice for lists under 1000 items.

Searching algorithms

Linear search

  1. Start at the first item.
  2. Compare it with the search item.
  3. If they are the same, stop.
  4. If not, move to the next item.
  5. Repeat until the end of the list is reached.
Exam tipLinear search is sequential and works on unsorted lists.

Searching algorithms

Binary search (1/3)

Median

The middle item when the numbers are in order. With an even number of items it is the mean of the middle two. In a binary search the higher of the two is chosen.

Searching algorithms

Binary search (2/3)

  1. The list must already be sorted in ascending or descending order.
  2. Select the median item.
  3. If it equals the search item, stop.
  4. If the median is too high, repeat with the sub-list to the left.
  5. If it is too low, repeat with the sub-list to the right.
  6. Repeat until the item is found or all items have been checked.
