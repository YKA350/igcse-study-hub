Why sort and search

Why sort and search

Millions of items may be stored, so searching must be efficient.

Sorted data is far easier to search, like a dictionary in alphabetical order.

Sorting arranges items in ascending order (1, 2, 3) or descending order (3, 2, 1).

Some algorithms are more efficient than others.

Bubble sort

Sorting and searching algorithms

Bubble sort

How it works (1/3)

Pass

One complete traversal (trip along) the list comparing pairs.

Exam tip It is called bubble sort because the largest items gradually move to the end like bubbles rising in water.
After pass 1 the largest is in place, after pass 2 the next largest, so the last comparisons can be left out to make it more efficient.
Careful A computer needs one extra pass with no swaps to know the list is sorted. It cannot just look at all the numbers at once.
Bubble sort

How it works (2/3)

Start at the beginning of the list.

Compare the values in positions 1 and 2. If they are not in ascending order, swap them.

Compare positions 2 and 3, and swap if necessary.

Continue to the end of the list.

Bubble sort

How it works (3/3)

If there have been any swaps, repeat from the beginning. Stop when a whole pass has no swaps.

Bubble sort

The flowchart variables

position starts at 1 and moves along the list.

length is the length of the list.

switch (swap counter) is reset to 0 at the start of each pass and increased by 1 every time two items are swapped.

At the end of a pass, if switch is 0 the list is sorted.

Merge sort

Sorting and searching algorithms

Merge sort

How it works (1/2)

Recursion

Repeatedly applying a method to the results of a previous application of the same method.

Exam tip For descending order, merge by taking the larger leftmost item each time. Show the splitting and merging stages in a table.

Split the list into two halves, then split again, until every list has one item. A one-item list is already sorted.

Merge sort

How it works (2/2)

Merge the lists back together in order.

When merging, compare the leftmost (lowest) item in each list and put the smaller into the new list first.

Repeat until all items are merged into one sorted list.

Efficiency of sorting algorithms

Efficiency of sorting algorithms (1/2)

Bubble sort Uses brute force

starts at the beginning and repeats the same task over and over until it finds a solution. It is the slowest.

Merge sort Uses divide and conquer

repeatedly breaks the problem into smaller sub-problems, solves them and combines the solutions. One of the most efficient.

Efficiency of sorting algorithms

Efficiency of sorting algorithms (2/2)

Bubble sort is far slower for lists of more than about 1000 items.

For small lists the time difference is too small to matter.

Bubble sort is easier to code, so it can be a good choice for lists under 1000 items.

Searching algorithms

Linear search (1/2)

Exam tip Linear search is sequential and works on unsorted lists.

Start at the first item.

Compare it with the search item.

Searching algorithms

Linear search (2/2)

If they are the same, stop.

If not, move to the next item.

Repeat until the end of the list is reached.

Searching algorithms

Binary search (1/2)

Median

The middle item when the numbers are in order. With an even number of items it is the mean of the middle two. In a binary search the higher of the two is chosen.

The list must already be sorted in ascending or descending order.

Select the median item.

Searching algorithms

Binary search (2/2)

If it equals the search item, stop.

If the median is too high, repeat with the sub-list to the left.

If it is too low, repeat with the sub-list to the right.

Repeat until the item is found or all items have been checked.

Searching algorithms

Best and worst case (1/2)

Linear search

Best case: Item is first: 1 comparison; Worst case for 1000 items: Item is last: 1000 comparisons, average 500

Binary search

Best case: Item is the median: 1 comparison; Worst case for 1000 items: About 10 comparisons (500, 250, 125, 63, 32, 16, 8, 4, 2, 1)

Binary search is far more efficient, but the list must be sorted first.

Searching algorithms

Best and worst case (2/2)

If a list is searched only once, a linear search is better.

If a large list is searched many times, sort it and use a binary search.

Once sorted, new items can be inserted in their correct places.
