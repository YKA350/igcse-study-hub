Understanding algorithms

What an algorithm is

Definition and example (1/2)

Algorithm

A precise method for solving a problem. It is a sequence of steps with a start and an end.

Sequence

An ordered set of instructions, carried out one after another.

Exam tip A satnav route between two cities is an example of an algorithm. Computers need every instruction to be unambiguous or they will not know what to do.
What an algorithm is

Definition and example (2/2)

It is unambiguous

the instructions cannot be misunderstood, e.g. "turn left" is clear but "turn" is ambiguous.

It can be used again and always gives the same result.

It provides a solution to a problem.

Most problems have more than one solution, so different algorithms can solve the same problem.

What an algorithm is

Successful algorithms

Exam tip Some sorting and searching algorithms are far more efficient than others. A new method is only an improvement if it is faster than the old one, such as an atlas.

Accuracy It must lead to the expected outcome, e.g. create a route from one city to another.

Consistency It must produce the same result every time it is run.

Efficiency It must solve the problem in the shortest time using as few computer resources as possible.

What an algorithm is

Algorithms and programs

An algorithm is a detailed design for a solution.

A program is that design implemented in a programming language.

Algorithms are first designed, then coded in a high-level language, which is similar to natural human language.

Displaying algorithms

Understanding algorithms

Displaying algorithms

Written descriptions

Careful "Wait for water to heat" is ambiguous because how hot is not stated. A computer algorithm must say "wait until the water reaches 100 °C".

The simplest way to express an algorithm.

Example, making instant coffee

fill kettle, turn on kettle, place coffee in cup, wait for water to boil, pour water into cup, add milk and sugar, stir.

Everyday tasks such as a recipe or flat-pack instructions are algorithms.

Displaying algorithms

Flowcharts (2/2)

Arrow

The logical flow of the algorithm

Flowchart

Shows an algorithm as a diagram. Each step is a symbol and symbols are linked with arrows showing the order.

Exam tip Use only the standard symbols. Nobody else could follow a flowchart that uses made-up shapes.
Displaying algorithms

Pseudocode

Pseudocode

A structured, code-like language used to describe an algorithm without the rules of any particular programming language.

It lets a developer concentrate on logic and efficiency.

It is easy to translate into any high-level language.

Different exam boards have their own versions. This course uses the Pearson Edexcel pseudocode.

Displaying algorithms

Worked example: adding two numbers

The two numbers typed in are stored in variables firstNumber and secondNumber.

The result is stored in the variable total.

Text to display goes in quotation marks, single or double.

No quotation marks when you want a variable displayed, otherwise the word total is shown instead of its value.

Operators, variables and constants

Arithmetic operators (1/2)

+: Meaning: Addition; Example: 8 + 5 = 13

−: Meaning: Subtraction; Example: 17 − 4 = 13

*: Meaning: Multiplication; Example: 6 * 9 = 54

/: Meaning: Real division, gives decimals; Example: 13 / 4 = 3.25

Operators, variables and constants

Arithmetic operators (2/2)

DIV

Meaning: Quotient, whole number only; Example: 13 DIV 4 = 3

MOD

Meaning: Modulus, the remainder; Example: 13 MOD 4 = 1

^: Meaning: Exponentiation, to the power of; Example: 3 ^ 2 = 9

Operators, variables and constants

Variables

Variable

A container used to store data. The stored value is not fixed, so one program can process different sets of data.

Operators, variables and constants

Constants

Constant

A container that holds a value that never changes, such as pi, the months in a year or the litres in a gallon.

Operators, variables and constants

Identifiers and naming (1/2)

Exam tip Be careful not to confuse a descriptive name with a long name. firstName tells the reader what data it holds.

Every variable and constant needs a unique identifier.

Use descriptive names, e.g. firstName rather than X.

Long names are easier to misspell, so keep them sensible.

Operators, variables and constants

Identifiers and naming (2/2)

Camel case

firstName. Capitals for each word: FirstName. Snake case: first_name.

Pick one convention and use it consistently.
