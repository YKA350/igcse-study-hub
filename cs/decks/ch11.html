Why test

Why test

Mistakes always happen however carefully a program is written.

Ariane 5 (1996) exploded after 39 seconds because a speed value was too big for a 16-bit variable that had been fine on Ariane 4.

Programs should be tested and evaluated before they go live.

Logic errors

Testing and evaluation

Logic errors

Logic errors (1/2)

Logic error

An error in an algorithm that gives incorrect or unexpected behaviour.

Order of precedence is BIDMAS

brackets, indices, division and multiplication, then addition and subtraction.

A loop whose variable is set to 1 inside the loop never reaches 10. That is an infinite loop, a loop that never ends because the stopping condition is never reached.

Logic errors

Logic errors (2/2)

Initialise the variable before the WHILE loop.

A range check using OR instead of AND accepts everything, e.g. year >= 7 OR <= 13.

Trace tables

Testing and evaluation

Trace tables

Trace tables

Trace table

A formal way of checking an algorithm's logic. Each column is a variable or output and each row records their values step by step.

Exam tip Trace tables can also find the value a variable holds at a given point in a program.

Runtime errors

Testing and evaluation

Runtime errors

Runtime errors

Runtime error

An error while the program is running because the operation is impossible, e.g. dividing by zero.

Runtime errors are the hardest to predict and spot.

Examples

dividing by zero, a file that cannot be found, an array index that does not exist.

Test data and test plans

Test data and test plans (1/3)

Normal

Purpose: Typical valid data; Example for ages 1 to 100: 45

Boundary

Purpose: Limits of the valid range; Example for ages 1 to 100: 1 and 100

Erroneous

Purpose: Invalid data that must be rejected; Example for ages 1 to 100: −5 or abc

Test data and test plans

Test data and test plans (2/3)

A test plan lists the test, test data, expected result and actual result.

Compare actual and expected output. Differences show errors.

Use debugging tools such as breakpoints, stepping and watching variables.
