Why test

Why test

  1. Mistakes always happen however carefully a program is written.
  2. Ariane 5 (1996) exploded after 39 seconds because a speed value was too big for a 16-bit variable that had been fine on Ariane 4.
  3. Programs should be tested and evaluated before they go live.

Logic errors

Logic errors (4/4)

  1. Order of precedence is BIDMAS: brackets, indices, division and multiplication, then addition and subtraction.
  2. A loop whose variable is set to 1 inside the loop never reaches 10. That is an infinite loop, a loop that never ends because the stopping condition is never reached.
  3. Initialise the variable before the WHILE loop.
  4. A range check using OR instead of AND accepts everything, e.g. year >= 7 OR <= 13.

Syntax errors

Syntax error

A breaking of the grammar rules of the language. The code cannot be compiled or translated.

  1. Writing prnit instead of print.
  2. Missing a closing bracket.
  3. Missing quotation marks.

Runtime errors

Testing and evaluation

Runtime errors

Runtime errors

Runtime error

An error while the program is running because the operation is impossible, e.g. dividing by zero.

  1. Runtime errors are the hardest to predict and spot.
  2. Examples: dividing by zero, a file that cannot be found, an array index that does not exist.
