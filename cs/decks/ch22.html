Why security matters

Network security

Why security matters

Why security matters (1/3)

Network security

Activities that protect a network and its data from threats such as viruses, hackers, denial of service, interception, theft and equipment failure.

Confidentiality Keeping data secret. Only authorised users see what they need, users must not misuse access, and data is encrypted.

Why security matters

Why security matters (2/3)

Correctness (integrity) Data must not change, or be changed, without authorisation, e.g. health records or a manufacturing control system.

Availability Systems must stay usable. Viruses and denial of service (DoS) attacks can slow or stop a network, steal or alter data and code.

Data may be needed to run the organisation, and losing it can bankrupt a business.

Why security matters

Why security matters (3/3)

It may be private, e.g. hospital patient details, and there is a legal duty to protect personal data or the hospital could be sued.

It may be financially valuable, e.g. planned sale prices a competitor could undercut.

Authentication and access

Network security

Authentication and access

Authentication and access (1/5)

Authentication

Checking the identity of a user, e.g. validating a username and password against a central server, or a PIN or fingerprint.

Access control

Decides which users can access which data and what they can do. Set up by system administrators.

Firewall

A hardware or software system that monitors and controls data moving between networks, using a set of rules (firewall policy).

Authentication and access

Authentication and access (2/5)

Physical security

Controlling physical access to critical parts of a network, e.g. locked server rooms, burglar alarms, security tagging.

Passwords are weak if written down or guessable like a pet's name, and programs can guess repeatedly.

Two-factor authentication adds a second check such as a code from a secure token or an SMS to your phone.

Authentication and access

Authentication and access (3/5)

Read-only access

open and read but not change or delete.

Read and write (modify) access

change and save.

Full control

also delete.

Authentication and access

Authentication and access (4/5)

Example

a shop worker can open a price list but not change prices.

Rules can block protocols (e.g. FTP), block addresses or whole country ranges, and stop data matching a hacking pattern.

Home computers use software firewalls. Businesses use hardware firewalls which are more flexible and faster.

Authentication and access

Authentication and access (5/5)

Electronic locks record entry and exit times and cards can be disabled if lost.

Anyone with physical access can bypass authentication, copy or delete data or install malware.

Cloud, NAS and USB

Network security

Cloud, NAS and USB

Cloud, NAS and USB (1/3)

Cloud advantages Provider maintains hardware so data stays available. Storage can grow in minutes. Off-site data survives fire, theft or power failure. Often includes back-up snapshots.

Cloud disadvantages Relies on a third party that could fail or go bankrupt. Data on the Internet could be hacked or set up wrongly, or intercepted in transit.

Cloud, NAS and USB

Cloud, NAS and USB (2/3)

Servers may be in another country with different data laws. Needs a reliable fast Internet connection.

NAS Network-attached storage is a device giving file storage to a network. Often designed for ease of use not security. Risks are default passwords not changed and software not updated.

Fix

only put data online if needed, use complex passwords, remove defaults and apply patches.

Cloud, NAS and USB

Cloud, NAS and USB (3/3)

USB flash drives Cheap and portable but easily lost and could be used to steal data. Encrypted drives need a code on a keypad.

Reduce risk

store data in multiple locations and encrypt data in transit and in storage.

Cyber attacks

Network security

Cyber attacks

Cyber attacks

Cyber attack

Any malicious attack on a network-connected device, to access data, delete or change it, make a system unavailable, or damage a device.

Cyber attacks

Social engineering (1/2)

Phishing A message that looks like it is from a trusted source (e.g. a bank saying there is fraud) tricks you into giving usernames, passwords or card details on a fake site. Check the web address.

Shoulder surfing Watching someone enter a PIN or password, e.g. at a cash machine.

Cyber attacks

Social engineering (2/2)

Pharming Directing users to a fake website that looks real. Malware changes the IP address for a domain name in the DNS cache or on DNS servers.

Prevent by checking the address, checking https and the security certificate, installing updates and antivirus.

Cyber attacks

Technical weaknesses

Unpatched software Software without the latest security updates. Makers release patches, and attackers use published weaknesses against systems not yet updated.

USB devices Any USB device may carry malware or copy data out.

Eavesdropping Intercepting data sent to or from another system by reading it without copying it. May use malware or special hardware.

Protecting systems

Network security

Protecting systems

Protecting systems (1/4)

Audit trail An automatic, unchangeable, chronological record of activity: date and time, what changed and who or what changed it. Ordinary users cannot read it.

It shows what happened in an attack and whether data was copied or modified.

Secure operating systems Choose an OS designed with security in mind for sensitive data.

Protecting systems

Protecting systems (2/4)

Effective network security Management, monitoring and trained technical staff to patch software, set policies, train users and watch for unauthorised access.

Design stage

decide on authentication, different access levels, warnings before risky actions such as mass deletion, encrypting stored data, and threats such as phishing and malware.

Protecting systems

Protecting systems (3/4)

Implementation

guard against bad programming practice, since poor quality code or deadline shortcuts create code vulnerabilities, which are code written so a security issue can be exploited.

Code reviews

by another, more experienced programmer (labour intensive and costly) or by automated software that flags common vulnerabilities. Often both.

Protecting systems

Protecting systems (4/4)

Modular testing tests each block of code as it is finished. Poor input validation could let a hacker crash the program.

Finding vulnerabilities

Network security

Finding vulnerabilities

Finding vulnerabilities (1/2)

Ethical hacking

Good hacking: looking for weaknesses in software and systems so they can be fixed. Bad hacking steals data or causes damage.

Penetration testing Authorised, legal attacks on an organisation's own systems to find weaknesses, using technical attacks and social engineering. A report goes to senior management.

Finding vulnerabilities

Finding vulnerabilities (2/2)

Commercial analysis tools Vulnerability scanners bought or hired that look for known issues, internally or externally. They must be kept up to date.

Review of policies Network and user policies are reviewed to check rules and training match the risks.
