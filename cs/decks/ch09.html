Why validate

Input/output

Why validate

Why validate (1/2)

Validation

Checking that data entered by a user or from a file meets specified rules.

Most programs need input from a user, a sensor or a file.

Helpful messages tell users what to enter and confirm success.

Why validate

Why validate (2/2)

Invalid data can make a program behave unexpectedly or stop.

Wrong input gives wrong output

Garbage In, Garbage Out (GIGO).

Validation cannot guarantee data is correct, only that it is reasonable.

Types of validation

Input/output

Types of validation

Range check

Ensures the data is within a specified range.

validNum is a Boolean status flag, False at first. The loop repeats until it becomes True.

Types of validation

Presence check

Ensures a value has been entered so the field cannot be left blank.

Types of validation

Look-up check

Tests that a value is one of a predefined set of acceptable values, held in a one-dimensional array.

Example

form names ['7AXB', '7PDB', '7ARL', '7JEH']. A loop compares the entry with each item.

If found, output Valid form, otherwise The form you entered does not exist.

Types of validation

Length check

Checks the number of characters is within a range, e.g. UK postcodes are 6 to 8 characters.

It does not prove the postcode is correct.

Testing validation rules

Input/output

Testing validation rules

Testing validation rules

Normal data Within the limits that should be accepted, e.g. 7 characters for a password that must be 6 to 8.

Boundary data At the outer limits, e.g. 75 and 100 for a rule >= 75 AND <= 100.

Erroneous data Data that should not be accepted, e.g. 0 for the rules above.

Text files

Text files (1/3)

Text file

A sequence of lines, each made of a sequence of characters.

File handle

A label for a resource the program needs. The program can only access the file through the operating system.

Files let a program keep data after it finishes, and load it again next time.

Text files

Text files (2/3)

Steps

open the file, read or write, then close it.

If a new file is created with the same name as an existing one, the old file is overwritten and lost.

Save an array by writing the items separated by commas. Read back by splitting on the comma.

Text files

Text files (3/3)

A 2D array of names and scores can be written to a file in the same way, then read back into a one-dimensional array and moved into a 2D array two items at a time.

A list is used when reading in, because it is dynamic and items can be added as they are read.

CSV files hold values separated by commas.
