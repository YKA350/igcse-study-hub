Why validate

Why validate

  1. Most programs need input from a user, a sensor or a file.
  2. Helpful messages tell users what to enter and confirm success.
  3. Invalid data can make a program behave unexpectedly or stop.
  4. Wrong input gives wrong output: Garbage In, Garbage Out (GIGO).
  5. Validation cannot guarantee data is correct, only that it is reasonable.
Validation

Checking that data entered by a user or from a file meets specified rules.

Types of validation

Types of validation

Range check

SET validNum TO False
WHILE validNum = False DO
  SEND 'Please enter a number between 1 and 10:' TO DISPLAY
  RECEIVE number FROM (INTEGER) KEYBOARD
  IF number >= 1 AND number <= 10 THEN
    SET validNum TO True
  END IF
END WHILE
  1. Ensures the data is within a specified range.
  2. validNum is a Boolean status flag, False at first. The loop repeats until it becomes True.

Types of validation

Presence check

SET userName TO ''
WHILE userName = '' DO
  RECEIVE userName FROM (STRING) KEYBOARD
END WHILE
SEND 'Hello' & userName TO DISPLAY
  1. Ensures a value has been entered so the field cannot be left blank.

Types of validation

Look-up check

  1. Tests that a value is one of a predefined set of acceptable values, held in a one-dimensional array.
  2. Example: form names ['7AXB', '7PDB', '7ARL', '7JEH']. A loop compares the entry with each item.
  3. If found, output Valid form, otherwise The form you entered does not exist.

Types of validation

Length check

RECEIVE postCode FROM (STRING) KEYBOARD
SET length TO LENGTH(postCode)
IF length >= 6 AND length <= 8 THEN
  SEND 'Valid' TO DISPLAY
ELSE
  SEND 'Invalid' TO DISPLAY
END IF
  1. Checks the number of characters is within a range, e.g. UK postcodes are 6 to 8 characters.
  2. It does not prove the postcode is correct.

Testing validation rules

Testing validation rules

Testing validation rules

Normal data

Within the limits that should be accepted, e.g. 7 characters for a password that must be 6 to 8.

Boundary data

At the outer limits, e.g. 75 and 100 for a rule >= 75 AND <= 100.

Erroneous data

Data that should not be accepted, e.g. 0 for the rules above.

Text files

Text files (2/2)

  1. Files let a program keep data after it finishes, and load it again next time.
  2. Steps: open the file, read or write, then close it.
  3. If a new file is created with the same name as an existing one, the old file is overwritten and lost.
  4. Save an array by writing the items separated by commas. Read back by splitting on the comma.
  1. A 2D array of names and scores can be written to a file in the same way, then read back into a one-dimensional array and moved into a 2D array two items at a time.
  2. A list is used when reading in, because it is dynamic and items can be added as they are read.
  3. CSV files hold values separated by commas.
