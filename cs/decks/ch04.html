Decomposition

Decomposition and abstraction

Decomposition

Decomposition (1/2)

Decomposition

Breaking a problem down into smaller, more manageable parts that are easier to solve.

It is usually the first step in problem solving.

Different teams can work on sub-problems at the same time.

Decomposition

Decomposition (2/2)

Errors are easier to spot and correct in small algorithms.

Code can be reused in other programs.

Abstraction

Decomposition and abstraction

Abstraction

Abstraction (1/2)

Abstraction

Removing or hiding unnecessary detail so that only the important points remain.

In everyday life, "a cat in the street" lets us picture a cat without every detail.

We abstract the basic details of a problem and represent them in a way a computer can process.

Abstraction

Abstraction (2/2)

A model is a simple version of something that shows how it works.

Models and simulations are cheaper and safer than the real thing, e.g. flight simulators, weather forecasting, designing cars and bridges.

Abstraction

Levels of abstraction (1/2)

Exam tip Traffic-flow models can ignore the colours of vehicles and ages of drivers.

The higher the level of abstraction, the less detail is needed.

A programmer writing a print command does not need to know how printing is done.

Abstraction

Levels of abstraction (2/2)

A driver turning a key does not need to know how the engine works.

High-level languages such as Python or Java are at a high level of abstraction, far from the 1s and 0s the processor understands. A translator converts them.

Subprograms

Subprograms

Subprogram

A self-contained module of code that performs a specific task and can be called by the main program when needed.

Separate algorithms such as computer entry, check win and check draw can be written once and reused.

The die example could be a subprogram called die that returns a random number from 1 to 6.
