Decomposition and abstraction

Computer Science · Problem solving · Last-minute notes · Book pages 23–30

Chapter in a nutshell

  • Computational thinking is the thought process of formulating problems and solutions so a computer can carry them out.
  • Decomposition breaks a problem into smaller parts.
  • Abstraction removes unnecessary detail.
  • Identify inputs, outputs, processing and initialisation.

1Computational thinking
Computational thinking
Computational thinking

The thought processes involved in formulating problems and their solutions so that the solutions can be effectively carried out by a computer.

  1. Define and analyse the problem.
  2. Create a structured solution, an algorithm.
  3. Code it in a form the computer can run.
  4. Skills: algorithm design, decomposition and abstraction. A fault in the design means the program will not work however good the coder is.
2Decomposition
Decomposition
Decomposition

Breaking a problem down into smaller, more manageable parts that are easier to solve.

  1. It is usually the first step in problem solving.
  2. Different teams can work on sub-problems at the same time.
  3. Errors are easier to spot and correct in small algorithms.
  4. Code can be reused in other programs.

3Abstraction
Abstraction
Abstraction

Removing or hiding unnecessary detail so that only the important points remain.

  1. In everyday life, "a cat in the street" lets us picture a cat without every detail.
  2. We abstract the basic details of a problem and represent them in a way a computer can process.
  3. A model is a simple version of something that shows how it works.
  4. Models and simulations are cheaper and safer than the real thing, e.g. flight simulators, weather forecasting, designing cars and bridges.
Model a die for a computer game.
Real dieshows a random number from 1 to 6
Essential featurerandom whole number 1 to 6
Ignorecolour, size, material
Codea routine that selects a random number 1 to 6
A virtual die is abstraction of a real die
Levels of abstraction
  1. The higher the level of abstraction, the less detail is needed.
  2. A programmer writing a print command does not need to know how printing is done.
  3. A driver turning a key does not need to know how the engine works.
  4. High-level languages such as Python or Java are at a high level of abstraction, far from the 1s and 0s the processor understands. A translator converts them.
Exam tipTraffic-flow models can ignore the colours of vehicles and ages of drivers.

  1. Start at a high level of abstraction, then add detail, moving to lower levels.
  2. Plan how to test the finished program, with test data and expected outcomes.
  3. A pattern such as the computer then the user taking turns shows a loop is needed.
5Subprograms
Subprograms
Subprogram

A self-contained module of code that performs a specific task and can be called by the main program when needed.

  1. Separate algorithms such as computer entry, check win and check draw can be written once and reused.
  2. The die example could be a subprogram called die that returns a random number from 1 to 6.
  3. Unit 2 explains subprograms in detail.
